# Expected differences for identity_diff.py --tiers and classify_dryrun.py.
#
# One case per line, its parts separated by " | ":
#   <case key> | family=<family> | kind=<a or b> [| keys=<k>,...] [| new=<verdict>] | <reason>
#
# The key is a case key of operand_probe.py, fixture_snapshot.py or classify_dryrun.py,
# matched whole: * stands for any run of characters other than /, \* for a star, \\ for a
# backslash.  family names the family branch the entry belongs to: bits, data, flow, move
# or comm.  With keys=, the entry allows a first-tier difference in those record keys only.
# With new=, it allows only that verdict on the branch, ok or !<ExceptionClass>, and the
# whole branch record must give it: no errors for ok, only that class for !X, and read,
# dec and tag agreeing.  The reason states the rule the new verdict follows.
#
# A case belongs here only when
#   (a) CLICK shows that the verdict before the change was wrong, or
#   (b) before the change, the field value made the code raise something other than a
#       FieldError or AddressError: a crash, not a verdict.  A kind (b) entry needs new=.
# An entry is judged only on a case it matches whose first tier differs.  There, a kind (b)
# entry whose base is not a crash is misused, and the tools exit 2.  An entry that allows
# no case is unused, never an error.
# A message-only change needs no entry: --tiers lists it apart.
#
# An entry stays until its family's branch has merged; after that, the next branch that
# touches this file removes it.  Never remove another family's entry because it matches no
# difference yet: that family's change has not landed.
